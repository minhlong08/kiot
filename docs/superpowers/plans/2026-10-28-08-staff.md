# Milestone 8 — Staff, Schedule, Timesheets, Payroll & Commission Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Employees (optionally linked to a login), shift definitions and a weekly drag-and-drop schedule, timesheets with check-in/out and late/early/overtime, salary templates, commission tables, payroll periods that generate paysheets and pay them through the cash book, and the staff settings screen.

**Architecture:** Pure calculations live in `packages/shared/src/staff.ts` (attendance from a shift and punches, paysheet from a template + attendance + commission base) so the API and the UI agree and tests are cheap. The API owns state in new Prisma models; payments go through `recordCash` (category "Chi lương", counterparty `employee`, `sourceType 'payroll'`), never a second money writer. Commission base = net sales of invoices whose `sellerId` is the employee's linked user, minus returns of those invoices, in the period.

**Tech Stack:** as before.

**Spec:** requirements §6; design (Staff/Payroll in scope; times are Vietnam time UTC+7, no DST).

## Global Constraints

- All earlier constraints. Codes: employee `NV`+6, payroll period `BL`+6, paysheet `PL`+6.
- Dates for schedules/timesheets are local calendar strings `YYYY-MM-DD`; shift times `HH:mm` local. A shift whose end ≤ start ends the next day (overnight).
- Attendance (shared `attendance(shift, checkIn, checkOut, rules)`): late = max(0, checkIn − start − lateGrace), early = max(0, end − checkOut − earlyGrace), overtime = max(0, checkOut − end − overtimeAfter) (minutes); worked = clamp(checkOut, …) − clamp(checkIn, …) − break. Rules from `settings.staff { lateGraceMinutes 5, earlyGraceMinutes 5, overtimeAfterMinutes 30, standardDays 26 }`.
- Timesheet statuses: `scheduled` (no punches), `present`, `absent`, `paidLeave`, `unpaidLeave`. Manual edits set `manual = true` and are audited.
- Salary template modes: `monthly` (amount × paidDays / standardDays, paidDays = present + paidLeave), `perShift` (amount × shifts present), `perHour` (amount × worked hours, 2 decimals then rounded to đồng); overtime pay = hourly rate × OT hours × overtimeRate% (hourly rate for monthly = amount / standardDays / 8); allowances `{ name, amount, per: 'month' | 'shift' }`; deductions `{ name, amount, per: 'month' | 'late' }` (per late occurrence).
- Commission table rules `{ scope: 'all' | 'group' | 'product', refId, type: 'percent' | 'fixed', value }`; the most specific rule wins per line (product > group > all); fixed = per unit sold (net of returned units).
- Payroll period lifecycle `draft → locked → (paid via paysheets)`; regenerating allowed only in `draft`; paying a paysheet is conditional (`paid < total`), partial payments allowed, each a cash voucher; cancelling a period with any payment → 409.
- Employee delete with schedules/timesheets/paysheets → deactivate. One employee per user; a user can see/punch only their own timesheet without `employees.view`.
- Permissions: `employees.*`, `payroll.*`; paying needs `payroll.edit` + `cashbook.create`.

## Review Focus

1. **Overnight shift** (22:00–06:00) punches across midnight compute worked/late/OT correctly (Task 1 shared tests).
2. **Paying the same paysheet twice concurrently** → total paid never exceeds total (Task 5).
3. **Regenerating a locked or partly paid period** → 409, nothing changes (Task 5).
4. **Returns of an employee's sales in the period** reduce the commission base; an employee without a linked user has 0 commission (Task 5).
5. **Schedule drag onto a day that already has the same shift for that employee** → no duplicate (unique constraint → 409) (Task 2).

### Task 1: Shared staff calculations

`packages/shared/src/staff.ts`: `minutesOf('HH:mm')`, `shiftWindow(date, shift) → { start: Date, end: Date }` (UTC from VN local; overnight), `attendance(window, breakMinutes, checkIn, checkOut, rules) → { worked, late, early, overtime }`, `computePaysheet(input) → { base, overtime, allowance, deduction, commission, bonus, total, lines: { label, amount }[] }`, `commissionFor(lines: { productId, groupId, qty, amount }[], rules)`; zod schemas `employeeInputSchema`, `shiftInputSchema`, `salaryTemplateInputSchema`, `commissionTableInputSchema`; `settings.staff` section.
- Tests: `08:00–17:00 with 60' break, in 08:12 out 17:45 → late 7, OT 15, worked 513`; `overnight 22:00–06:00, in 21:58 out 06:40 → late 0, OT 10`; `monthly 7,800,000 with 24 paid days of 26 → 7,200,000`; `perHour 25,000 × 7.5h → 187,500`; `late deduction 50,000 × 3 lates`; `product rule beats group rule beats all`.

### Task 2: Employees, shifts & schedule API

Models: `Employee { id, code, name, phone, email, branchId, position, userId Int? @unique, birthday, idNumber, address, startDate, salaryTemplateId?, commissionTableId?, note, isActive, searchText }`, `WorkShift { id, branchId, name, start, end, breakMinutes, color, isActive }`, `ScheduleEntry { id, employeeId, shiftId, date, @@unique([employeeId, shiftId, date]) }`. Routes: `/api/employees` CRUD + list/filter/search/export; `/api/work-shifts` CRUD; `GET /api/schedule?from&to` (entries + employees + shifts of the branch), `POST /api/schedule { employeeId, shiftId, date }`, `POST /api/schedule/move { id, employeeId, date }`, `DELETE /api/schedule/:id`, `POST /api/schedule/copy-week { fromMonday, toMonday }` (skips existing).
- Tests: `employee code NV + link to a user; second employee on the same user → 409`, `assign, move, delete; duplicate → 409 DUPLICATE_SHIFT`, `copy week copies entries once`, `employee with schedule is deactivated on delete`.

### Task 3: Timesheets API

Model `Timesheet { id, employeeId, shiftId, date, checkIn?, checkOut?, status, late, early, overtime, worked, manual, note, @@unique([employeeId, shiftId, date]) }` (created lazily from schedule). Routes: `GET /api/timesheets?from&to&employeeIds` (merges schedule + rows, computes minutes), `PUT /api/timesheets { employeeId, shiftId, date, checkIn, checkOut, status, note }` (manual, audited), `POST /api/timesheets/punch` (current user's employee: nearest scheduled shift today; in then out), `GET /api/timesheets/summary?from&to` (per employee: shifts present, paid leave, absent, late count/minutes, OT minutes, worked minutes).
- Tests: `punch in then out sets checkIn/checkOut and late/OT`, `punch without a schedule today → 409 NO_SHIFT`, `manual edit recomputes minutes and marks manual`, `summary counts statuses`.

### Task 4: Salary templates & commission tables API

Models `SalaryTemplate { id, name, mode, amount, overtimeRate, allowances Json(String), deductions Json(String), isActive }`, `CommissionTable { id, name, rules String, isActive }`. CRUD routes `/api/salary-templates`, `/api/commission-tables` (delete in use → deactivate).
- Tests: `template validation (perHour needs amount > 0)`, `commission table rules round-trip`, `in-use template cannot be deleted`.

### Task 5: Payroll API

Models `PayrollPeriod { id, code, name, branchId, from, to, status, createdById, createdAt }`, `Paysheet { id, code, periodId, employeeId, base, overtime, allowance, deduction, commission, bonus, total, paid, detail String, status }`. Routes: `/api/payroll-periods` list/create (`{ name, from, to }` → generates paysheets for active employees of the branch with a template), `POST /:id/regenerate` (draft only), `POST /:id/lock`, `POST /:id/cancel`, `PUT /api/paysheets/:id { bonus, note }` (draft only, recomputes total), `POST /api/paysheets/:id/pay { amount, fundId }` (conditional on `paid + amount ≤ total`), `GET /:id/export`.
- Tests: `period generates paysheets from timesheet summary + commissions (returns netted)`, `employee without a user → commission 0`, `concurrent pays never exceed total`, `regenerate locked → 409`, `cancel with payments → 409`, `pay writes a 'Chi lương' voucher to the employee`.

### Task 6: Admin — employees, shifts, schedule, timesheets, staff settings

`/employees` list (filters: branch, position, status; columns Mã NV, Tên, SĐT, Chức danh, Chi nhánh, Tài khoản, Trạng thái) + form (link login select, salary template, commission table); `/work-schedule`: week navigator, shift definitions side panel, grid employees × 7 days, shift chips dragged (HTML5 drag-and-drop) from the palette onto a cell to assign and between cells to move, × to remove, "Sao chép tuần trước"; `/timesheets`: week grid with each cell showing in/out and colored late/OT, click to edit (status, times, note), "Chấm công" button for the signed-in user; `/staff-settings`: work rules (`settings.staff`) + roles & permissions matrix (reuse `RolesSettings`).
- Tests: `dropping a shift chip on a cell posts the assignment`, `moving an entry posts move`, `timesheet edit posts times and status`.

### Task 7: Admin — salary templates, commissions, payroll

`/payroll`: periods list with totals (Tổng lương, Đã trả, Còn cần trả), create dialog (month picker → from/to), period view with paysheets table (expand for detail lines, bonus edit in draft), lock, pay dialog per paysheet (amount, fund) and "Thanh toán tất cả"; templates tab; `/commissions`: tables with rules editor (scope picker: all / group / product search).
- Tests: `paying a paysheet posts the remaining amount and fund`, `commission rule editor saves product and group rules`.
