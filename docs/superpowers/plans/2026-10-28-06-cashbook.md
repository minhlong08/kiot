# Milestone 6 — Cash Book & Debts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** The Sổ quỹ screen over the cash-voucher core built in M3–M5: funds (cash, several bank accounts, e-wallets), user categories, period summary (opening / in / out / closing), manual Phiếu thu / Phiếu chi with optional debt posting, fund-to-fund transfers, cancellation rules, printing, export — plus the settings screens for funds, categories and POS payment defaults.

**Architecture:** No new money writers: manual vouchers go through `recordCash` and, when they settle a debt, `postPartnerLedger`. Balances are always computed (`opening + Σ in − Σ out` over completed vouchers), never stored. Auto vouchers (those with a `sourceType` other than `manual`/`transfer`) are read-only here; they change only through their source document.

**Spec:** requirements §7; design §8 (affectsPnl on categories feeds the M9 P&L).

## Global Constraints

- All earlier constraints. Manual prefixes from settings: `cashIn 'PT'`, `cashOut 'PC'`; fund transfer pair `CQ` (one code shared by the two vouchers' `sourceCode`).
- Fund balance for a period: opening = `fund.openingBalance + Σ(in − out)` of completed vouchers before `from`; closing = opening + in − out within the period. "Tổng quỹ" sums every fund the user can see.
- Branch scoping: users see vouchers of their session branch; company-wide funds (`branchId null`) show only that branch's vouchers in them. Admins may pass `branchId=all`.
- Manual voucher with counterparty customer/supplier and `postToDebt: true` writes a partner ledger row (`docType 'manualVoucher'`): Phiếu thu from customer −amount; Phiếu chi to supplier −amount; Phiếu chi to customer +amount; Phiếu thu from supplier +amount.
- Cancelling: manual and transfer vouchers can be cancelled (with reversing ledger rows); auto vouchers → `409 AUTO_VOUCHER` ("Hủy chứng từ gốc …").
- Funds referenced by vouchers cannot be deleted (deactivate instead); system categories cannot be deleted or renamed.

## Review Focus

1. **Summary across a period boundary** — vouchers dated exactly at `from` belong to the period, not the opening balance (Task 2 test).
2. **Cancelled vouchers** never count in any balance (Task 2).
3. **Transfer between funds of different branches** refused (Task 2).
4. **Manual phiếu thu for a customer with postToDebt** reduces their debt and cancelling restores it (Task 2).
5. **A cashier without `cashbook.view`** sees no cash book data, even through export (Task 2).

### Task 1: Funds & categories API

`/api/cash-funds` (existing GET extended: `?all=1` incl. inactive, each with current balance) + `POST`, `PUT /:id`, `DELETE /:id` (deactivate when used) — fields: type, name, bankName, bankBin (new column, for VietQR), accountNumber, accountName, branchId|null, openingBalance, isActive; `/api/cash-categories` CRUD (kind, name, affectsPnl; system ones locked). Migration adds `CashFund.bankBin`. Perms `cashbook.*` (funds/categories edit also `settings.edit`).
- Tests: `create bank fund with opening balance shows balance`, `delete used fund deactivates`, `system category cannot be deleted`.

### Task 2: Vouchers API

`GET /api/cash-vouchers` (filters: fundIds, fundType (`cash|bank|ewallet|all`), from/to, kind, categoryIds, createdBy, counterpartyType, affectsPnl, status, search code/counterparty; returns `items`, `total`, `summary { opening, in, out, closing }` for the filtered funds and period), `GET /:id` (with source link: type/id/code), `POST /api/cash-vouchers { kind, fundId, amount, categoryId, counterpartyType, counterpartyId?, counterpartyName, note, at?, postToDebt }`, `POST /api/cash-vouchers/transfer { fromFundId, toFundId, amount, note }`, `POST /:id/cancel`, `GET /export`, `GET /:id/print` (voucher data + store + amount in words via `amountInWords(n)` in shared — "Một triệu hai trăm nghìn đồng").
- Tests: `summary opening/in/out/closing with a voucher exactly at from`, `cancelled excluded`, `manual receipt posts customer debt and cancel restores`, `auto voucher cancel refused`, `transfer creates paired vouchers; other-branch fund refused`, `no cashbook.view → 403 on list and export`, shared `amountInWords(1_200_000) === 'Một triệu hai trăm nghìn đồng'`.

### Task 3: Admin — Sổ quỹ

`/cashbook`: tabs Tiền mặt / Ngân hàng / Ví điện tử / Tổng quỹ; summary bar (Quỹ đầu kỳ, Tổng thu, Tổng chi, Tồn quỹ); sidebar filters (quỹ (for bank/ewallet tabs), thời gian, loại chứng từ thu/chi, loại thu chi, người tạo, đối tượng, hạch toán KQKD, trạng thái); toolbar: Lập phiếu thu, Lập phiếu chi, Chuyển quỹ, Xuất file; columns Mã phiếu, Thời gian, Loại thu chi, Người nộp/nhận, Giá trị (+/−, colored); expanded detail with source document link, note, creator, In phiếu, Hủy (manual only). Voucher form: counterparty type select + picker (customer/supplier picker reused; employee = user select; other = free name), category select filtered by kind (+ quick create), amount, fund, "Tính vào công nợ" checkbox (customer/supplier only, shows current debt), note, date.
- Test: `creating a phiếu chi posts kind out with category and fund`; `summary bar shows API summary`.

### Task 4: Settings — funds, categories, POS defaults

Settings sections: "Sổ quỹ" (funds table with type, account, bank BIN, opening balance, branch, active; categories table), "Bán hàng" (POS: default fund per method, VietQR account = choose a bank fund (fills `settings.pos.bankQr` from its BIN/number/name), receipt size, print after payment, require customer, rounding). 
- Test: `choosing the VietQR fund saves bankQr`.

### Task 5: E2E

`e2e/cashbook.spec.ts`: after a POS sale (API) and a return, the Tiền mặt tab lists TTHD and TTTH; create a Phiếu chi "Chi phí điện nước" 500,000 → closing balance drops by 500,000; cancel it → restored; transfer 1,000,000 cash → bank shows in both tabs.
